# ADR-001 · 地图采用 WebView2 + AMap 1.4

日期：2026-11-07
状态：已采纳

## 背景

地点填写需要「在地图上点选位置」。用户明确选择要有地图界面（参考另一个软件 ExifCraft 的做法），而不是只给一个搜索框。

## 考虑的方案

| 方案 | 地图界面 | 防盗用 | 体积 | 用户配置 |
|---|---|---|---|---|
| A. 软件内搜索框，无地图 | ✗ | 中高（可配数字签名） | +0 | 简单 |
| B. 嵌入高德 JS API 地图 | ✓ | 依赖域名白名单 | +1 MB | 需填白名单 |
| C. 原生 Windows 窗口嵌 WebView2 | ✓ | 同 B | +1 MB | 同 B |

## 决定

选 **B**，用 `webview_flutter_windows`（WebView2）+ AMap JS API。

理由：
- 用户要地图点选体验
- WebView2 用 Evergreen 模式，体积只增约 1 MB（不是打包整个 Chromium）
- Win11 自带运行时，Win10 大多数也有

## 关键约束（踩坑后确认）

- **必须用 AMap 1.4，不能用 2.0**。2.0 依赖 WebGL，Flutter 的纹理合成 WebView 里 GPU 上下文起不来，`new AMap.Map()` 同步阻塞不返回。
- 页面必须由本地 HTTP 服务器提供（`127.0.0.1`），不能用 `file://`——高德域名白名单不接受 `file://`。
- 白名单填 `127.0.0.1` 即可，端口不参与匹配，所以端口可以随机。
- 所有高德调用（地图、逆地理编码、搜索）统一走 JS API，**不能混用 Web 服务 REST 接口**——两者的 Key 类型不同，混用会导致「平台类型不对」。

## 代价

- 构建机需要开启 Windows 开发者模式（插件符号链接）。**最终用户不需要。**
- 极少数旧版 Windows 10 可能缺 WebView2 运行时，软件会提示安装。
- 白名单填 `127.0.0.1` 的防盗用强度有限（别人在自己电脑上跑本地网页也能用），已如实告知用户，用户接受。

# ADR-002 · 地名精简为「市 · 区 · 具体地点」

日期：2026-11-07
状态：已采纳

## 背景

高德返回的完整地址会包含省份、街道、门牌，例如「江苏省南京市江宁区秣陵街道翠湖花园小区」。预设里的地点组件通常排在一行说明文字的位置，这个长度会溢出或挤得很紧。

## 决定

从结构化字段重新拼装，只取三段：**市 · 区 · 具体地点**，用圆点分隔。

具体地点优先级：建筑名 > 社区名 > 街道名 > 乡镇。

## 为什么不用字符串裁剪

完整地址的分隔符和顺序不固定（有的带街道有的不带），裁剪容易切出新缺字。用结构化字段拼装更可靠。

## 兜底

结构化字段全空时，退回用完整地址，不返回空字符串。

# ADR-003 · 坐标转换（WGS-84 ↔ GCJ-02）

日期：2026-11-07
状态：已采纳

## 背景

EXIF 里存的是 GPS 原始坐标（WGS-84），高德地图用的是国内偏移坐标系（GCJ-02）。不转换会偏 300–500 米，查出来的地点会落在隔壁街区。

## 决定

在 `app/lib/settings/coords.dart` 实现双向转换：

- `wgs84ToGcj02`：查地名前，把照片坐标转成高德坐标
- `gcj02ToWgs84`：如果用地图选点需要写回照片（当前不写，保留能力）

## 实现要点

正算用公开公式，误差 1–2 米。反算无解析逆，用 6 次迭代逼近，误差小于 0.5 米。境外坐标（超出中国范围）原样返回。

## 相关决定

**坐标不写入照片**。从照片读出的坐标只用来查地名；导出时默认移除 GPS 信息，保护隐私。

# ADR-004 · 设置面板独立于工作台设置

日期：2026-11-07
状态：已采纳

## 背景

原先把明暗模式存在 `workspace.json` 里。新增高德密钥等配置后，如果继续放在同一个文件，「清理使用记录」会把密钥一起删掉。

## 决定

新增 `app-settings.json` 单独存放应用级设置（高德 Key/密钥、自动填地点开关），与工作台布局分开。

`workspace.json` 继续存界面布局和明暗模式。

## 密钥存储

做简单混淆（逐字节 XOR + Base64），**明确不称为加密**。它只防「打开文件一眼看到」，不防逆向。本地软件无法真正保护放在用户机器上的密钥，已如实告知用户。

# ADR-005 · 测试必须串行跑

日期：2026-11-07
状态：已采纳

## 背景

`flutter test` 默认并行。多个测试共用同一个 `LUMACRAFT_DATA_DIR`，并且依赖真实时间等待（2 秒目录核对、导出落盘），并行时互相干扰、误报失败。

## 决定

**统一用 `-j 1` 串行。** 约 3 分钟跑完 206 项。

## 为什么不改造测试让它们能并行

那需要每个测试文件用独立数据目录、并去掉真实时间依赖（改成注入时钟）。改造量大，收益只是省 2 分钟。当前用明确的规范和文档约束更划算。

已在 `TEST_BASELINE.md` 写明，并在项目台账 R12 记录。
