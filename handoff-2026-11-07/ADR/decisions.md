# 技术决策记录

每条写清「背景 → 决策 → 被否决的备选 → 代价」。**被否决的备选尤其重要**：它记录了为什么不那么做，避免后续又绕回去。

前 11 条来自 2026-11-05 的交接材料（0.8.0 时期），后 5 条是 0.18.0 期间新增或修订的。

---

## ADR-001 · 用 Flutter，桌面优先

**背景**：产品需要 Windows 与后续 Android 共用排版，桌面又需要自由画布和专业操作。

**决策**：采用 Flutter；当前交付 Windows x64，Android 另行适配。

**被否决**：产品方案比较过 Qt/QML 和 Tauri，取舍是手机体验与跨端界面复用。**没有把 Android 模板当成已完成跨端。**

**代价**：Windows 上嵌入 WebView2 需要插件与开发者模式（仅构建机）；原生功能要写 C++ 桥接。

## ADR-002 · 本地记录用版本化 JSON，不用数据库

**背景**：需要照片补填、用户预设、草稿、界面与导出偏好本地恢复。

**决策**：按职责分成多个 JSON 文件，schema `version: 1`；写入串行，先写 `.pending` 再 rename；照片以完整路径为键。

**被否决**：**没有**做过 SQL/ORM 方案的正式比较，因此不能声称"性能比较后放弃 SQLite"。

**代价**：记录与路径强绑定（已用内容指纹 + 拍摄时间缓解）；无通用迁移框架，遇到未知版本直接拒绝。

## ADR-003 · 一套文档 + 横竖布局覆盖，不复制两份

**背景**：预设同时适配横、竖、方照片。复制两套独立文档会让共同的文字/素材内容漂移。

**决策**：`StyleDocument` 存通用内容，另加横/竖布局差异覆盖；方图用通用布局。`StyleScene` 统一几何与绘制。锚点只用于适配，**不限制拖动范围**；换锚点时换算 X/Y，尽量保持视觉位置。

**被否决**：独立复制全部横竖文档。用户也否决了「跨区域拖动受锚点限制」的行为。

**代价**：布局覆盖的合并逻辑复杂，改动要小心。

## ADR-004 · 独立无窗口 C++ 工具做色彩转换

**背景**：导出需要真正的色彩管理和 ICC 嵌入。**仅贴 sRGB 标签并不会把非 sRGB 像素变成 sRGB。**

**决策**：独立无窗口 C++ 工具，用 WIC 把源配置转到 Windows 标准 sRGB 像素，RGBA 进入共用画布；JPG 写 APP2、PNG 写 iCCP，嵌入实际目标配置。

**被否决**：此前「普通编码」的做法不足以证明真实转换。未找到其它跨端色彩库的正式比较记录，不虚构否决理由。

**代价**：只支持 Windows；打包必须带 `lumacraft_color_tool.exe`，只拷主程序会导出失败。

## ADR-005 · 导出快照、冲突决策与暂存发布

**背景**：批量导出过程中用户仍可修改界面；目标文件可能重名、出错或被外部改变。

**决策**：导出开始时**冻结**本轮参数、样式与目标；冲突时明确三选一（取消 / 替换 / 编号保留）；保护原图与符号链接；先完整暂存再发布；失败重试保持原任务快照。

**被否决**：原先「自动编号一律保留」改为明确三选一；**批内同名不允许以替换方式相互覆盖**。

**代价**：需要检测目标文件的外部变更；失败可能留下 pending 文件；取消要等当前步骤完成，不宣称即时中断原生解码。

> 0.17.4 在此基础上前进：冲突三选一改为四选一（新增「跳过同名」）。

## ADR-006 · `.lmp` 作为唯一的完整分享格式

**背景**：需要离线分享、分组/批量导入和预设兼容性。

**决策**：统一 `.lmp`：JSON 格式，含版本与能力声明，校验结构、数值、分组引用及素材；字体使用稳定 ID，新字体标记 `bundledFontsV1`。

**被否决**：更长的后缀由用户改为 `.lmp`；**未知功能不静默忽略**，旧版会明确拒绝导入。

**代价**：带新特性的预设旧版无法导入（属预期保护）。

> 0.17.4 补充：二维码/文本代码用于轻量分享，但**带图片标识的预设超出容量**，只能用 `.lmp`。两者并存，`.lmp` 仍是完整格式。

## ADR-007 · 内置工作库与发行版只读隔离

**背景**：用户要在制作阶段直接修改内置样式，再封成最终不可修改的内置资源。

**决策**：`assets/builtins/library.json` 是封包基线；`LUMACRAFT_AUTHORING=true` 时改读独立的 `builtin-working.json` 并提供维护入口；默认 `false`（发行版）不读工作稿，内置库只读。

**被否决**：用户否决了「制作阶段只能复制成用户预设、无法直接维护内置」的工作流；发行版仍保留用户复制修改的通道。

**代价**：**保存工作库不等于已写回 assets、也不等于已封包。** 封包前必须显式导出，否则用户的作品不会进入发行版。

> **封正式版的具体步骤见 `../HANDOFF.md` 的「发行版与制作版」一节**，那里列了 8 处必须隐藏的入口和 12 项核对清单。

## ADR-008 · 8 款 OFL 字体

**背景**：需要衬线/无衬线/手写的中英文，离线可用且控制包体。

**决策**：8 款 OFL 官方原文件；中文用区域子集（Lite）及单字重，英文用小型可变文件；同类中文有回退；保留旧的 Georgia / 微软雅黑键名以兼容旧数据；菜单沿用现有下拉，用对应字体预览。

**被否决**：用户取消 Futura（**不得重新加入**）；不按示例文字裁字；不做独立的字体选择界面。

**代价**：中文字体体积大，包体约 68 MB。

## ADR-009 · 界面一致性与交互约定

**背景**：此前反复出现小字、标签重叠、图标不一致、正式界面与 HTML 原型不符。

**决策**：共用顶栏/底栏、控件与文字样式；文字 + 下划线标签页、阴影层级、暖金强调色；表单用框外独立标签；菜单无动效；Ctrl/Shift/框选选择，Ctrl+J 复制，**Ctrl+D 按当前焦点取消**（在照片上清照片选择，在组件上清组件选择）。

**被否决**：用户否决了勾选框代替常规选择、过小文字、混用 Flutter 原生下拉外观、Ctrl+D 用作复制、冗余的设置面板。

**代价**：所有新控件必须复用既有样式，不能直接套框架默认外观。

## ADR-010 · 模式切换动画

**背景**：整页缩放和淡入淡出曾让操作显得不自然、画布变暗。

**决策**：`WorkspaceModeRoute` 260ms；共用顶栏底栏不变，画布保留；系统开启「减少动态效果」时关闭动画；下拉菜单不应用这个效果。

**被否决**：先后否决整页缩放、画布淡入淡出。用户试过侧栏轻滑后，要求叠加淡入淡出，并确认修正了变暗问题。

**代价**：动画逻辑分散在路由与各界面，改动需同时检查。

## ADR-012 · 地图用 WebView2 + AMap 1.4

**背景**：用户明确要求「在地图上点选位置」，不接受只有搜索框。

**决策**：用 `webview_flutter_windows`（WebView2）+ 高德 JS API。WebView2 走 Evergreen 模式，体积只增约 1 MB。

**被否决**：方案 A（软件内搜索框无地图）——用户选了有地图的；方案 C（自写 C++ 直连 WebView2）——能用现成插件就不自己造轮子。

**关键约束（踩坑后确认，务必遵守）**：
- **必须用 AMap 1.4，不能用 2.0。** 2.0 依赖 WebGL，Flutter 的 WebView 是纹理合成，GPU 上下文起不来，`new AMap.Map()` **同步阻塞不返回**，连定时器都不执行。
- 插件必须用 `AMap.plugin([...], cb)` 显式加载，写在 URL 的 `&plugin=` 不可靠。
- 页面必须由本地 HTTP 服务器提供（`127.0.0.1`），`file://` 会被高德域名白名单拒绝。
- 白名单填 `127.0.0.1` 即可，端口不参与匹配。
- 所有高德调用统一走 JS API，**不能混用 Web 服务 REST 接口**（Key 类型不同，混用会报「平台类型不对」）。

**代价**：构建机需开 Windows 开发者模式（最终用户不需要）；极少数旧 Win10 缺 WebView2 运行时会提示安装；白名单填 `127.0.0.1` 防盗用强度有限，已如实告知用户。

## ADR-013 · 地名精简为「市 · 区 · 具体地点」

**背景**：高德返回的完整地址含省份、街道、门牌（如「江苏省南京市江宁区秣陵街道翠湖花园」），预设里的地点组件通常排在一行说明文字位置，这个长度会溢出。

**决策**：从结构化字段重新拼装，只取三段，用圆点分隔。具体地点优先级：建筑名 > 社区名 > 街道名 > 乡镇。

**为什么不用字符串裁剪**：完整地址的分隔符和顺序不固定，裁剪容易切出新缺字。

**兜底**：结构化字段全空时退回完整地址，不返回空字符串。

**代价**：失去了省份信息（一般不需要）；同名的区和市会做去重处理。

## ADR-014 · 坐标转换 WGS-84 ↔ GCJ-02

**背景**：EXIF 存的是 GPS 原始坐标（WGS-84），高德用国内偏移坐标系（GCJ-02）。不转换会偏 300–500 米，查出的地点落在隔壁街区。

**决策**：`app/lib/settings/coords.dart` 实现双向转换。正算用公开公式（误差 1–2 米）；反算无解析逆，用 6 次迭代逼近（误差 < 0.5 米）。境外坐标原样返回。

**相关决定**：**坐标不写入照片**。从照片读出的坐标只用来查地名；导出时默认移除 GPS，保护隐私。

**代价**：境外拍摄的照片查高德没有意义（超出服务范围，会给出明确提示）。

## ADR-015 · 应用设置独立于工作台设置

**背景**：原先明暗模式存在 `workspace.json`。新增高德密钥后，如果继续放在同一文件，「清理使用记录」会把密钥一起删掉。

**决策**：新增 `app-settings.json` 单独存应用级设置（高德 Key/密钥、自动填地点开关），与工作台布局分开。`workspace.json` 继续存界面布局与明暗模式。

**密钥存储**：简单混淆（逐字节 XOR + Base64），**明确不称为加密**。它只防「打开文件一眼看到」，不防逆向。本地软件无法真正保护放在用户机器上的密钥，已如实告知用户。

**代价**：清理记录时两个文件都要处理；密钥保护强度低。

## ADR-016 · 测试统一串行跑

**背景**：`flutter test` 默认并行。多个测试共用同一个 `LUMACRAFT_DATA_DIR`，并且依赖真实时间等待（2 秒目录核对、导出落盘），并行时互相干扰、误报 5 项失败。

**决策**：统一用 `-j 1`。约 3 分钟跑完 206 项。

**为什么不改造测试让它们能并行**：需要每个测试用独立数据目录、并去掉真实时间依赖（改成注入时钟）。改造量大，收益只是省 2 分钟。用明确规范和文档约束更划算。

**代价**：跑测试慢一些；新写测试时要注意不能用真实时间等待，否则并行下更不稳定。

> 详情见 `../TEST_BASELINE.md`，风险编号见项目台账 R12。
