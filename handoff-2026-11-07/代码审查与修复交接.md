## 2. 高优先级修复

### 2.1 批量导出续导沿用原批次数据

**问题与定位**

- 正常导出会固定每张照片的样式、有效拍摄字段、输出文件名和重名处理决定。照片没有单独样式时会用默认样式。续导记录目前只保留路径、名称和导出选项，续导从当前照片记录拿样式和手填字段，缺少原照片读取出来的有效拍摄字段，也没有保留替换授权。结果可能是续导的边框和批次前半段不同、画面拍摄字段缺失，或已确认替换的文件无法输出。
- 当前流程在新的恢复进度写入前就清掉旧记录。如果续导刚开始又退出，剩余任务可能失去恢复入口。
- 主要入口见 [正常导出](<D:/AI Agent/LumaCraft/app/lib/main.dart:1099>)、[继续导出](<D:/AI Agent/LumaCraft/app/lib/main.dart:219>)、[恢复记录](<D:/AI Agent/LumaCraft/app/lib/export/export_recovery.dart:7>) 和 [发布输出文件](<D:/AI Agent/LumaCraft/app/lib/export/export_task.dart:16>)。

**实施建议**

1. 用户确认导出范围和重名处理后，持久化原批次任务。每项记录源路径、固定后的目标路径、样式（含素材）、有效拍摄字段、旧版胶片标记，以及允许替换的目标当时的文件状态。批次另存格式、画质、尺寸和 EXIF/GPS 选项。
2. 批次清单写一次，共用样式存一份。逐张仅更新小型进度记录和处理中照片的尺寸。先写临时文件并完成替换，再让进度记录指向新清单。续导开始时保留旧记录，直到新记录可读。记录写失败时给出可见错误或日志。
3. 继续执行现有约定，跳过中断时正在处理的一张、失败过的照片和缺失源文件，避免循环。续导仍需检查目标是否变化和原片保护。旧版路径记录可用当前拍摄字段和默认样式作回退，旧记录没有替换授权时保护现有文件。
4. 留意照片本身在中断期间被替换这一边界。续导可恢复当时的样式、字段和决定，源图像素仍来自源路径；如要加入源文件身份校验，先和用户确定遇到变化时的处理方式。

**验收**

用两张以上的隔离照片建立一批导出任务，含默认样式、有 EXIF 的照片和已确认替换的目标。中断后修改当前样式，再续导，检查输出图的边框、拍摄字段、ICC 和文件名。另改动一个原本获准替换的目标，确认其内容受到保护。Windows 分别走窗口关闭、真正强制终止、空闲时正常关闭三种流程，逐一查下次启动提示和记录文件。旧版记录读取也做一次。现有 `export_recovery_test.dart`、`export_resume_test.dart` 和 `export_workspace_flow_test.dart` 可复用。

### 2.3 编辑模式的目录补查被通知计时器覆盖

**问题与定位**

编辑器 `startWatching()` 用同一个 `watchTimer` 保存每 5 秒一次的补查和收到系统通知后的 300 毫秒延时。第一个通知到达后，会取消定时补查，后续若系统漏报，列表就可能停留在旧状态。浏览模式已经把两者分开，可直接参考。见 [编辑器监控](<D:/AI Agent/LumaCraft/app/lib/ui/editor/editor_page.dart:672>)、[浏览页监控](<D:/AI Agent/LumaCraft/app/lib/main.dart:297>)。

**实施建议与验收**

用独立计时器处理定时核对和通知合并，切目录、调整递归和关闭编辑器时停止旧任务。避免旧目录的核对结果覆盖新目录，避免慢扫描叠加。监控、列目录和异步刷新失败至少写日志或给出界面提示。浏览、编辑分别用真实文件走彻底删除、回收站、改名、移出目录，等定时器执行完后检查界面上的数量和文件名。关键回归用例是先触发并处理一次真实通知，再暂停测试中的通知来源，确认编辑界面仍能通过定时核对发现下一次文件变化。现有 `live_delete_refresh_test.dart`、`live_recycle_refresh_test.dart`、`watch_coverage_probe_test.dart` 可复用。

## 3. 之后再做的性能与体积优化

- **大图内存。** Windows 色彩工具通过 stdout 返回 RGBA，Dart 收完整输出后再次复制。接近 1.34 亿像素时，单份 RGBA 已超过 500 MB。先记录大图在解码、合成、编码几个阶段的峰值，再逐项试减少整块复制或改变传输方式。保持 sRGB 转换和 ICC 写入，复核广色域、EXIF 方向、JPG/PNG 与 HEIC。见 [色彩管理入口](<D:/AI Agent/LumaCraft/app/lib/export/color_management.dart:166>)。
- **目录和列表。** 高优先级的计时器修复完成后，再用大量照片和子目录量刷新耗时，观察慢扫描是否重叠、通知是否反复触发全量列表更新。先建立时间和刷新次数基线，再决定是否改扫描和缓存方式。
- **交付大小。** 现有 0.18.0 文件夹逐文件合计 **72,814,471 字节（69.44 MiB）**。8 个字体文件合计 **37,638,636 字节（35.90 MiB，约 52%）**，Flutter 引擎约 20.30 MiB，`app.so` 约 9.89 MiB，内置预设库约 0.97 MiB。最大的三款字体是霞鹜文楷轻便版和思源宋体、黑体中文版本。包内优化应先看字体。
- **保持功能完整的缩包顺序。** 先试同字库、同字形、同覆盖范围的可分发字体方案，核对授权、家族名、字符映射和实际渲染。固定文案可按字符审计，允许用户自由输入的字体不能按 UI 或内置预设用字直接裁剪，否则生僻字和旧预设会回退到别的字体。其次检查单份字体与内置素材是否重复、压缩资产是否会增加启动耗时。保留现有字体选择、断网可用、ICC 和 Windows 运行时依赖，再比较前后包大小；目前没有可承诺的缩包幅度。交付仍按用户要求给文件夹。
