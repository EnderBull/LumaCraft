## 2026-11-07 · 高德地图：连续返工六轮

这是本项目最耗时的一次排查，四个独立问题叠加，症状却都表现为「地图空白」。

### 坑 1：AMap 2.0 在 Flutter WebView 里挂死

**症状**：地图区域一片空白，底部状态停在第 2 步，**等了远超 12 秒也没有任何变化**，连我设的 watchdog 定时器都没触发。

**真实原因**：AMap 2.0 用 WebGL 渲染。Flutter 的 WebView 是把网页渲染成纹理再贴到界面上，这种环境下 GPU 上下文起不来，`new AMap.Map()` **同步阻塞不返回**，导致后续所有代码（包括定时器注册）都不执行。

**教训**：
- 定时器没触发，说明是**同步阻塞**，不是网络慢或逻辑错。这个信号一开始就该抓住。
- 在嵌入环境里用第三方库，先确认它的渲染依赖。参考软件（Qt 浏览器）有正常 GPU，所以同一个版本在它那里没问题——**平台不同，同一个库的行为可能完全不同**。

**修法**：改用 AMap 1.4.15（Canvas 渲染）。

### 坑 2：隐藏 WebView 没有尺寸就不执行脚本

**症状**：后台自动填地点永远超时。

**真实原因**：`webview_flutter_windows` 的文档里有一句「Pages do not perform layout until they have nonzero bounds」。控制器不挂到界面上就没有尺寸，页面不布局，脚本不执行。

**教训**：读库文档时要留意「headless」「layout」「bounds」这类关键词，它们通常埋在注释里。

**修法**：`initialize()` 后立刻 `setSize(Size(900, 700))`。

### 坑 3：占位符替换漏了引号，整段脚本失效

**症状**：地图页面加载了（有内容），但搜索按钮和地图点击都没反应。看起来像「事件没绑定」。

**真实原因**：页面里用字符串拼接 `'...&key=' + __KEY__`。我在一处把 `__KEY__` 替换成**不带引号**的值，结果 JS 变成 `'...key=' + 120abcxyz`，那是**非法变量名**，整个 `<script>` 块解析失败，一行都不执行。

**教训**：
- **改了生成内容的代码，必须把生成结果打印出来看一遍。** 代码本身不报错，错的是产物。
- 同一功能的多个页面用了不同的替换写法，改一处漏另一处。**同类代码要么共用一份，要么加测试盯住。**
- 「按钮点了没反应」和「请求发出去了但没回」，是两种完全不同的故障，要能区分。

**修法**：三处替换统一带引号，并加断言测试。

### 坑 4：`AMap.PlaceSearch` 未加载导致后续绑定全部中断

**症状**：地图能画出来，但搜索和点击完全没反应。

**真实原因**：插件写在 script URL 的 `&plugin=` 参数里，在 1.4 里不总是生效。`new AMap.PlaceSearch()` 抛错，把它之后的**所有代码**（包括 `map.on('click')` 和按钮绑定）都跳过了。地图已经建好，所以看起来正常。

**教训**：一段初始化代码里，任何一步抛错都会让后面的步骤静默失效。**整段包 try/catch 并把错误显示出来**，比事后猜快得多。

**修法**：改用 `AMap.plugin([...], callback)` 显式加载，插件就绪后再建图。

## 2026-11-07 · 地点写了但界面不显示

**症状**：地图选完地点、点了「使用这个地点」，窗口关闭了，但信息面板的地点栏仍显示「缺失」。

**真实原因**：数据**已经写进去了**。问题在 `PhotoInfoForm` 更新输入框前会先比较「新旧数据有没有变化」，而记录里的字段 Map 是**原地修改**的：

```dart
state.fields['place'] = text;   // 改的是同一个 Map 对象
```

比较时新旧两边指向同一个对象，读到的都是新值，判定为「没变化」，输入框不刷新。

中间我还自作聪明加了个 `identical(a, b) return true` 的快捷判断，让问题更糟。

**教训**：
- **原地修改的数据，比较「引用是否相等」或「内容是否相等」都没有意义**——旧值已经不存在了。
- 这类情况应该**无条件同步**，而不是试图判断变化。
- 「数据没写进去」和「界面没刷新」要分开验证：直接读文件确认，比看界面可靠。

**修法**：每次重建都把值同步进输入框。

## 2026-11-06 · 删除照片不刷新，连续两天被退回

**症状**：用户在软件外删了照片，底栏数量不变。

**真实原因（三个叠加）**：
1. 编辑模式把 `late final List<File>` 整块重新赋值，运行时抛异常，刷新逻辑第一步就中断，异常被异步回调吞掉不留痕迹。
2. 删照片时缩略图被立刻 `dispose`，但界面还在引用它，随即报「Cannot clone a disposed image」，画面卡在旧状态。
3. 解码用的 `ImmutableBuffer` 没释放，照片被软件占用，用户根本删不掉。

**教训**：
- **验证方式不算数比不会修更糟。** 我只测了扫描器本身，没测软件真的看到变化；只手动试了浏览模式，就拿「代码路径相同」推断编辑模式也没问题。
- 一个功能有多套实现时，必须**每套分别验证**。
- 异步回调里的异常必须落到界面或日志，不能静默吞掉。
- 打开的文件句柄必须配平。

## 2026-11-06 · 导出中断提示连修两版都没生效

**症状**：导出中被中断，下次打开没有任何提示。

**真实原因**：我只改了 Dart 侧的标记逻辑，**原生 `flutter_window.cpp` 里 `NoteVoluntaryExit()` 仍在删进度记录**。点 X 关闭和任务管理器「结束任务」都会先发 `WM_CLOSE`，两条路径都被删掉记录。

**教训**：**跨语言的功能必须两侧一起查**。只改一侧，另一边会把效果抵消掉。

**顺带一个知识点**：Windows 任务管理器的「结束任务」会先发正常关闭信号，**不等于强制杀死**。要真正强杀测试，用 `taskkill /F /IM xxx.exe`。

## 通用教训（已写入 AGENTS.md）

| 教训 | 出处 |
|---|---|
| 有现成同类实现，先读再动手 | 地图返工六轮后才去读参考软件源码 |
| 现象相同，原因未必相同；同一症状试两次没解决就必须拿证据 | 把「空白」当成单一问题，逐个猜 |
| 一次只改一处 | 同时改了隐藏窗口→可见窗口 + 静态标签→动态加载，无法判断哪个起作用 |
| 不做「看起来更完整」的额外设计 | 把「测试连接」做成真实查询，而参考软件只验证脚本加载 |
| 改了生成内容的代码必须打印产物核对 | Key 漏引号 |
| 改了 A 处必须查配套的 B 处 | 原生侧漏改；三处占位符替换不一致 |
| 报成功前确认跑的是新产物 | 构建缓存导致旧 exe 继续运行 |
