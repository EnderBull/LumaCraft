# LumaCraft 仓库技术审查（只读初审）

日期：2026-11-09；对象：https://github.com/EnderBull/LumaCraft ，公开 main 分支。

## 审查范围与证据等级
已直接查看 README、AGENTS.md、项目台账以及关键源码 `app/pubspec.yaml`、`app/lib/main.dart`、`editor/style_document.dart`、`editor/style_render.dart`、`render.dart`、`photo_state.dart`、`editor/preset_store.dart`、`export/export_options.dart`、`export/export_task.dart`、`ui/app_theme.dart`、`ui/place_picker.dart`、`settings/place_lookup.dart`、`settings/map_page_server.dart`、`settings/webview_geocoder.dart` 的公开内容。未成功将整个仓库克隆到执行环境，也未运行 Flutter、测试、Windows 或 Android 构建。故本文件是**部分源码级初审**，不应描述为全仓库审计完成。

## 已核实的技术事实
1. Flutter/Dart 单工程位于 `app/`；`pubspec.yaml` 当前 `version: 0.20.1+66`，Dart 约束 `>=3.4.0 <4.0.0`。
2. 关键依赖包含 `image ^4.2.0`、`file_selector ^1.0.3`、`flutter_svg ^2.2.3`、`qr ^4.0.1`、`zxing2 ^0.2.4`、`webview_flutter_windows ^1.3.1`、`shelf ^1.4.3` 等。地图 WebView 依赖明确是 Windows 平台实现。
3. `main.dart` 的 `Workshop` 汇集文件列表、选中状态、`PhotoStore`、`PresetStore`、导出状态、目录扫描、文件监控、窗口控制和 UI。这是 Android 适配的主要耦合热点。
4. `StyleNode` / `StyleDocument` 对组件属性、位置及 JSON 序列化作建模，`StyleScene` / `StyleGeometry` 依据照片比例和组件字段渲染，属于优先复用对象。
5. `photo_state.dart` 以 `File(path)` 读取 EXIF，支持 JPEG/HEIC 相关解析和 PNG EXIF。UI 输入过滤与实际解码器能力不能直接画等号。
6. `render.dart` 中部分普通图片处理调用 `image` 库并直接操作路径；完整样式导出另有代码路径。不能因 `renderPhoto` 存在就认为它覆盖所有编辑器渲染情况。
7. `ExportOptions` 定义 JPG/PNG、1–100 质量、自定义长/短边、EXIF/GPS 选择；导出最长边 16384 像素、最多约 1.34 亿像素。
8. `ExportJob` 保存 `File` 来源与目标字符串；`publishExport` 采用同目录临时文件及 rename 发布，并检查替换冲突。在 Android SAF/MediaStore 上不能原样照搬路径操作。
9. `PresetStore` 以 JSON 文件持久化预设和分组，`builtinLibrary` 制作版与发行版行为不同。内置预设只读规则有对应代码。
10. `ui/app_theme.dart` 共享明暗配色，但使用 `Microsoft YaHei UI` 和 Windows 字体回退；Android 应替换 UI 字体策略，不可影响预设字体资源。
11. 地图经 `webview_flutter_windows` 实现；`MapPageServer` 在本机 `127.0.0.1` 起 HTTP 服务承载高德 JS API；代码注释指出高德 1.4 版和 WebGL/WebView 差异。Android 需验证 WebView、loopback 白名单及用户 Key/安全密钥。
12. README 记录了 Windows 端 41 套预设、8 款内置字体、.lmp/二维码/文本分享及已有断点续导；Android 明确不要求断点续导。README 测试命令 `flutter test -j 1`，因为部分测试共享数据目录，**并行测试会互相干扰**。
13. 项目台账注明 Android 目前仅模板工程，英语界面尚未完成；Windows HEIC 使用系统解码扩展。README 和台账表明高德 Key 需用户自备。
14. `AGENTS.md` 明确：先分析再改文件、变更需确认、对用户用中文解释、遵守文件删除审批、维护项目台账、验证真实产物。实施时必须遵守。

## 高优先级风险与建议
| 等级 | 风险 | 必须完成的验证/改造 |
|---|---|---|
| P0 | HEIC 解码是 Windows 专属路径 | 在 Android 12+ 用真实 HEIC/HDR/EXIF 样本验证解码与颜色；确定替代实现及许可 |
| P0 | Windows-only WebView 插件被 Android 编译路径直接引用 | 将地图呈现与地理编码的浏览器依赖抽象为平台接口；验证 Android WebView、localhost 服务、JS 通信和安全密钥 |
| P0 | 导出用 `File` / rename，Android 相册使用 URI/MediaStore | 拆分“命名与冲突策略”和“实际写入目标”，让后者有 Windows/Android 平台实现 |
| P0 | `Workshop` 绑定路径、目录扫描、窗口控制 | 分离共享会话/业务控制与 Windows 桌面 UI；Android 独立页面，不复用桌面窗口布局 |
| P0 | 大尺寸照片内存与图像纹理上限 | 对 12/24/48/61MP 多格式输入，分别验证预览与全尺寸导出；失败不静默缩图 |
| P1 | 旧版预设未知 JSON 字段重序列化可能丢失 | 用新字段导入→修改→导出→再导入测试；必要时采用保留原始扩展字段的模型 |
| P1 | `app_theme.dart` UI 字体偏 Windows | 跨平台 UI 字体抽象；预设内置字体保持一致，做文字换行 Golden 测试 |
| P1 | Android 分享 URI 访问权限与会话持久化 | URI 权限保存、必要时副本、缓存清理、丢失后的恢复提示 |
| P1 | Android 后台导出生命周期 | 验证前台服务要求、系统通知、取消、锁屏、厂商后台限制；无进程终止续传承诺 |
| P1 | Windows 导出恢复逻辑与 Android 需求不同 | 共享可复用的任务快照/失败重试，Android 不自动启用 Windows 断点恢复 |
| P1 | 测试可能共享文件目录 | 首先隔离测试状态目录；在消除冲突前保留 `flutter test -j 1` |
| P1 | 两平台独立版本号但单一 `pubspec.yaml` | 设计平台版本映射、Android versionCode、Git 标签、签名密钥和 CI 参数 |

## 建议的逻辑代码边界（目标架构，不是当前仓库已有目录）
- `domain/`：预设模型、组件属性、命名与尺寸规则、图像元数据策略、会话数据结构。
- `application/`：选图后的业务流程、预设编辑状态、导出任务、日志、会话恢复。
- `platform/`：照片读取与 URI、目标写入、后台任务、WebView、系统分享、通知、平台设置。
- `ui/desktop/`：保留现有完整 Windows 工作台并渐进调整。
- `ui/mobile/`：新建 Android 首页、预设选择、轻量属性面板、逐张编辑、全屏预览、导出状态和设置。

不建议先把工程拆成多个 Flutter 应用；优先在同一个工程里形成清晰接口边界。先写兼容性验证样例，再决定确切文件和模块迁移数量。

## 仍需真实仓库环境完成的审计任务
- 全量检索 `Platform.isWindows`、`dart:io`、`File`、所有 MethodChannel、Windows 插件及硬编码盘符/路径。
- 审查完整导出调用链、预览与最终图像一致性、HEIC 和 ICC 处理链。
- 审查 `.lmp` 序列化、图片资源内嵌、二维码容量与未知字段处理。
- 审查 Android 工程已有 manifest、Gradle、SDK、Java/Kotlin 版本与插件兼容性。
- 检查测试目录、Golden 基线、现有 GitHub Actions 工作流和签名方案。
- 运行 `flutter analyze`、`flutter test -j 1`、Windows 基线构建与 Android 最小构建。
