# LumaCraft Android 需求规格说明（PRD）

版本：规划稿 1.0 · 日期：2026-11-09 · 状态：50 轮访谈完成；待工程验证

## 1. 产品定位
Android 是 Windows LumaCraft 的移动精简版。Windows 负责完整预设设计；Android 负责照片导入、应用预设、修改已有组件的非结构性属性、逐张修正文字和 EXIF 显示内容、批量导出。维持一个 Flutter 项目，尽可能共享预设模型、字体、渲染、导出、业务设置。Android 最低版本为 Android 12（API 31）。主要面向 6GB RAM 及以上的中端设备；更低配置尽可能兼容，失败时明确报告，不静默降质。

## 2. 功能需求与验收条件
| ID | 范围 | 已确认需求 | 验收举例 |
|---|---|---|---|
| FR-01 | Android 首页 | 照片处理优先；提供选择照片、管理预设、恢复上次会话入口 | 首次打开可直接选图；有未完成会话可主动继续 |
| FR-02 | 选图 | 系统相册 + 文件管理器；单张、多张；接收 Android 系统分享 | 可从相册、文件管理器、其他 App 传入照片 |
| FR-03 | 文件关联 | `.lmp` 文件关联，并支持文件、二维码、文本代码的导入导出 | 文件管理器打开 `.lmp` 能进入导入流程；预设可跨端交换 |
| FR-04 | 预设库 | 复用 Windows 当前搜索、分组、收藏、预设管理和保存规则 | 内置预设只读、用户预设保存行为与 Windows 一致 |
| FR-05 | 编辑边界 | 仅允许编辑已有组件的非结构性属性；禁止新增/删除组件、移动位置和调整层级 | 所有非结构性属性可编辑；无法改变预设结构 |
| FR-06 | 文字组件 | 修改文字、字体、字号、颜色、透明度等 | 文字属性实时更新预览 |
| FR-07 | 非文字组件 | 形状的颜色/描边/不透明度等，图片/Logo 的资源替换、缩放和透明度等 | 替换现有资源后 `.lmp` 保存、分享、重载正确 |
| FR-08 | 批次级样式 | 同一批次使用一个预设，样式修改作用于全部照片 | 切换照片仍保持相同预设样式 |
| FR-09 | 照片级内容 | EXIF 自动读取；每张照片的文字和拍摄信息可独立编辑 | 修改一张的文字不影响其他照片 |
| FR-10 | 预览 | 编辑界面实时预览；点击进入独立全屏预览 | 全屏可放大查看细节和切换照片 |
| FR-11 | 布局 | 完全复用 Windows 当前横图、竖图、方图的适配规则 | 同样输入与预设，布局高度一致 |
| FR-12 | 字体 | 完全复用 Windows 内置 8 款预设字体；不支持外部字体导入 | 两端字体名单与预设标识对应一致 |
| FR-13 | 渲染 | 高度一致：组件位置、比例、换行应一致；允许少量抗锯齿差异 | 基准图像对比在约定容差内 |
| FR-14 | 输入 | 与 Windows 支持的照片格式一致，含 JPEG 和 HEIC/HEIF；不增加 RAW | 手机端 HEIC 真实样本可解码并读取支持的 EXIF |
| FR-15 | 导出 | JPG/PNG；原尺寸或自定义长边/短边；JPG 质量可调 | 各尺寸/格式组合符合输出设置 |
| FR-16 | 元数据 | 拍摄参数和 GPS 独立选择是否保留；沿用 Windows 的默认值和更新规则 | GPS 关闭不泄漏坐标；EXIF 与设置对应 |
| FR-17 | 命名 | 复用 Windows 命名模板、冲突处理与文件安全规则 | 不意外覆盖原图；同名处理可预测 |
| FR-18 | 后台导出 | 允许切换应用、锁屏，尽可能持续处理；通知展示进度与取消 | 支持 Android 12+ 的后台任务场景；系统终止后不要求断点续导 |
| FR-19 | 导出锁定 | 导出期间禁止继续编辑或发起新任务 | 只能查看进度或取消；完成后解锁 |
| FR-20 | 错误处理 | 单张失败跳过并记录；结束时列明结果，支持仅重试失败项 | 成功项保持；不自动降低画质；全局存储错误停止 |
| FR-21 | 会话 | 同时只保存一个编辑会话；手动保存预设、自动保存会话 | 应用重启后恢复照片、样式与逐张文字修改 |
| FR-22 | 文件存取 | 优先持久化来源 URI 权限，必要时创建工作副本，清理缓存 | 原文件缺失时明确提示；不会覆盖原图 |
| FR-23 | 新任务 | 从外部分享照片总是开启新会话；已有未完成会话先警告 | 取消不破坏旧会话；确认后替换 |
| FR-24 | 撤销 | 复用 Windows 现有撤销/重做机制 | 属性、资源、逐张文字操作可正确撤销（需适配验证） |
| FR-25 | 主题 | 复用 Windows 明暗主题，Android 增加跟随系统 | 切换应用主题不改变照片输出 |
| FR-26 | 语言 | 复用 Windows 实际已实现的语言资源；Android 增加跟随系统 | 未支持的系统语言合理回退；不改动预设文字 |
| FR-27 | 地图 | 复用 Windows 高德 JS API 的搜索/点选/位置信息填写与 Key 逻辑 | Android WebView 能加载和回传位置；不申请设备定位权限 |
| FR-28 | 日志 | 本地错误日志；用户主动查看/导出；不自动上传 | 日志脱敏，不包含照片、GPS 和 API 密钥 |
| FR-29 | 网络 | 离线优先；高德地图选点按需联网；不需要账号或云同步 | 无网络仍能编辑和导出；地图失败可解释 |
| FR-30 | 分发 | GitHub Releases 优先，独立 Windows/Android 版本号、独立发布；无应用内检查更新 | Android 通过签名 APK 更新；Windows 可独立发布 |
| FR-31 | 设备与 UI | Android 12+，手机竖屏优先，兼容横屏和平板 | 手机竖屏完成核心流程；横屏和平板界面无关键控件溢出 |
| FR-32 | 质量 | 核心逻辑测试、Golden 图像对比、GitHub Actions CI；小范围多机 Beta | CI 与约定真机测试通过才发布正式版 |

## 3. 明确不做
首版不支持 Android 完整预设结构编辑（添加/删除/移动组件、图层排序）、RAW 输入、云同步、账户系统、多编辑项目、导出多任务队列、进程终止后自动断点续导、自动崩溃上传、应用内检查更新、手机 GPS 定位、外部字体导入、独立的 Android 预设排版算法。

## 4. 约束与例外
1. 用户希望 Android 输入与 Windows 对等，但 Windows HEIC 当前依赖 Windows 系统解码，因此 Android 需要兼容性等价的实现，不能直接复用操作系统解码路径。
2. Windows 当前图像导出代码存在 `exportMaxEdge=16384` 与约 1.34 亿像素总量限制；“能力与 Windows 一致”是沿用这些限制，不是承诺处理无限大图。
3. Windows 当前 README 说明地图使用用户自备高德 Key/安全密钥，Android 复用该用户配置模式，不能误写成内置公共 Key。
4. Windows 项目台账截至 2026-11-09 显示英语界面尚未实现，故“复用全部语言”目前可能仅为简体中文；Android 不得凭空承诺现成的多语言资源。
5. 对较新 `.lmp` 中未知属性采用尽可能兼容与降级提示的策略；保留未知字段是**必须验证/可能需改造**的工程目标，不应假定当前序列化已经支持。
6. Android 的原始文件 URI 与 Windows 路径并不等同；文件命名与冲突规则可复用，但写入介质需适配系统 API。

## 5. 发布门槛
Alpha：Android 能运行，完成选择照片 → 应用预设 → 正确预览 → JPG 导出；记录已知限制。
Beta：实现访谈内约定的主要功能，运行自动化与主要真机测试，GitHub Pre-release 收集反馈。
v1.0：已确认范围全部实现；无未修复的阻断/严重缺陷；Windows 无已知回归；跨平台渲染达到约定容差；关键高像素/后台/权限/会话案例在目标设备验证通过。
