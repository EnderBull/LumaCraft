# LumaCraft Android 分阶段实施计划（执行前审查稿）

日期：2026-11-09 · 实施原则：单一 Flutter 工程；独立 Android 开发分支；共享模块通过 Windows 回归测试后可提前合并；Android Alpha/Beta/v1.0 分阶段发布。

## 分支和准入规则
- Android 主开发分支建议 `feature/android`；每项相对独立的重构在短分支完成、审查后按需合入 `main`（具体命名可按仓库既有规范调整）。
- `main` 必须保持 Windows 可编译、现有核心测试通过、关键 Golden 无异常变化。
- Android 未完成功能通过平台入口隔离，不让 Windows 启动路径依赖 Android 专属插件。
- 每次提交/合并前：基础分析、单元测试、渲染回归；改动平台层时追加目标平台验证。
- 遵守仓库 `AGENTS.md`：任何拟修改文件先解释、获得授权；本计划仅提出改造方向，不等同于授权修改仓库。

## P0：锁定基线与完成全量源码审查
目标：确认当前 Windows 可运行状态及依赖全貌，消除“以为能共享”的假设。
任务：核对完整树与 Git 状态；检查 AGENTS/台账；检索 Windows 专用依赖；梳理完整解码→EXIF→预设→渲染→导出→落盘调用图；记录现有 Windows 操作与截图；建立可重现输入数据集。
交付：模块/依赖清单、风险台账、Windows 运行和测试基线、Android 最小编译可行性结果。
完成标准：`flutter analyze` / `flutter test -j 1` 的实际结果有记录；关键平台耦合与数据流具备源码依据。此阶段不重构功能。

## P1：跨平台可行性尖峰验证（Spike）
目标：优先验证四个高风险点，而不是先设计大量移动端 UI。
任务：Android 12+ 真机或模拟器启动；通过系统选图读取真实 JPEG/HEIC；同预设渲染 JPG；保存到相册/SAF；独立验证高德 JS WebView/127.0.0.1 与用户 Key；测量 12/24/48/61MP 内存；保留完整记录。
交付：小型实验性 Android 闭环、风险结论、各依赖的取舍，不合格则调整实现路线。
完成标准：能解释每个关键功能如何在 Android 实现，或列出明确阻塞项。实验不要求最终 UI，但不得破坏 Windows。

## P2：明确共享核心边界，渐进式抽离
目标：两个界面使用同一套业务规则，而非复制两份算法。
任务：抽离预设模型/序列化与未知字段保留；共享布局、字体与渲染；抽离导出尺寸、命名、EXIF/GPS；定义 `PhotoSource`、`ExportSink`、`MapService`、`SettingsStore` 等平台接口；保护既有 Windows 接口行为。
交付：可复用领域/应用层、Windows 适配实现、完整测试。
完成标准：Windows 原有操作和 Golden 正常；每个合入模块既有行为不变，Android 能复用至少一个真实业务闭环。

## P3：Android Alpha — 核心照片处理闭环
任务：照片处理优先首页、相册/文件导入、预设库现有规则、选择一套预设、编辑界面实时预览、独立全屏预览、JPG/PNG 输出、长短边与质量选择。
交付：可安装签名测试 APK（仅内部/Alpha 使用）、关键流程演示和已知问题清单。
完成标准：至少一张 JPEG 与 HEIC 在目标设备完成预设套用和正确导出；Windows 保持正常。暂不以高级批量/背景任务作为 Alpha 门槛。

## P4：Android 编辑器与预设互通
任务：已有文字/形状/图片/Logo 非结构属性编辑；图片资源替换；批次共享样式、逐张独立文字；撤销重做；`.lmp`/二维码/文本分享；预设保存规则；地图 JS 选点；主题/语言自动跟随系统。
交付：功能型 Beta 候选。
完成标准：Windows 创建的复杂预设在 Android 可导入、正确显示、改动非结构属性、保存后 Windows 可再次读取；未知字段不会静默破坏；同批次照片级文字独立。

## P5：Android 存储、会话恢复与后台批量
任务：URI 持久权限/必要副本；单会话恢复、外部分享/文件关联；后台导出通知及取消；导出时 UI 锁定；单张失败跳过/只重试失败；全局错误终止；缓存与诊断日志。
交付：Beta 版预发布、测试说明、问题报告模版。
完成标准：锁屏/切应用背景导出验证；恢复未完成编辑；失败项重试且不会意外重复或覆盖成功文件；无照片和密钥自动上传。

## P6：跨平台一致性、性能与正式发布
任务：标准照片/预设集 Golden 比较；高分辨率压力测试；Android 12+ 多品牌设备和横屏/平板验证；GitHub Actions 运行逻辑测试/Golden/平台构建；独立 Android 版本、签名、Release 资产命名及说明；Alpha/Beta 反馈修复。
交付：Android v1.0 签名 APK、Release、可复用构建说明、用户简明帮助与测试报告。
完成标准：所有已确认范围实现，无已知阻断或严重问题；Windows 无已知回归；真实 61MP 典型流程受控成功或有清晰可解释限制；GitHub Actions 检查通过。

## 自动化测试建议
- 单元：尺寸计算、命名冲突、EXIF/GPS 开关、预设序列化/兼容、批次共享样式与单张覆盖、恢复状态。
- Golden：横/竖/方图，各字体、形状描边、图片 Logo、长短边、多色/透明度、EXIF 缺失、背景/纹理。
- 端到端（优先人工真机）：Android URI/分享接入、高德 WebView、锁屏后台导出、系统回收进程、低内存、HEIC/ICC、目标目录失效。
- 现有测试可能共享数据目录：在确认隔离前继续运行 `flutter test -j 1`，不要直接切并行。

- 共享核心改造时需要改动的确切文件清单：必须在 P0 完整审计后列出，不应在未读全部代码时假定。
