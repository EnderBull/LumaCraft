## 工具版本与使用方式

- 工程内 Flutter 3.47.9、Dart 3.13.7。现有 Android 模板使用 AGP 9.1.0、Gradle 9.3.1、JDK 17、SDK API 36、NDK 28.2.13676358。P0 以 Android 12（API 31）验证运行，产品最低版本将在移动端实施时落实，当前模板仍使用 Flutter 默认值。
- Android 工具、模拟器数据和 Gradle 缓存集中放在 `app/.toolchain/android-p0/`。从 `app` 下用 `. .\tools\android-p0-env.ps1` 启用当前 PowerShell 会话的环境。
- Flutter 启动时的远程版本查询会对 SDK 自带的 Git 仓库执行 `git fetch --tags`，本机该请求曾停滞。下列命令使用 `--no-version-check`，沿用工程固定 SDK。
- Android 模板包名为 `com.example.lumacraft`，P0 调试构建用调试签名。正式应用 ID 和正式签名在发布阶段处理。

## Android 调试构建复现

从 `app` 目录执行。

```powershell
. .\tools\android-p0-env.ps1
java -version
.\android\gradlew.bat --version
adb devices -l
flutter --no-version-check build apk --debug --no-pub --target-platform android-x64
```

首次构建需要下载 Gradle 依赖。如果本机需要系统代理，给当前终端的 Flutter 和 Java 设置当前代理地址即可。Flutter 使用 `HTTP_PROXY` 和 `HTTPS_PROXY`，Java 使用 `JAVA_TOOL_OPTIONS` 中的 `-Dhttp.proxyHost`、`-Dhttp.proxyPort`、`-Dhttps.proxyHost`、`-Dhttps.proxyPort`。地址取本机实际配置，避免写入仓库。调试 APK 的目标是 API 31 模拟器的 x86_64 架构。

已验证 JDK 17.0.21.0.2、SDK 命令行工具 22.0、ADB 37.0.1 和 Gradle Wrapper 9.3.1 可运行。已安装 Android API 36、Build Tools 36.0.0、NDK 28.2.13676358、模拟器 37.2.13 和 Android 12 x86_64 原生镜像。SDK 压缩包按 Google 官方索引校验。Gradle 发行包按官方 SHA-256 校验。

首次下载出现多次传输停滞。完整文件由已校验的分段补齐，大文件写入项目专用缓存后再重跑。项目本地 Gradle 缓存下的 `gradle.properties` 记录当前机器的代理，Maven Central 已验证可直连并设置为不经代理。系统代理变化后需同步此本地配置。

本机实际通过的构建命令如下。Flutter 的 `build apk` 已编译 Dart 和资源，但调用的无前缀 `assembleDebug` 还会触发插件库的注解提取，并因额外依赖下载受阻。`:app:assembleDebug` 直接完成应用的打包。执行前启用上述环境，保留 Flutter 已生成的 `app/android/local.properties`；本机 Gradle 用户目录下的 `init.d/lumacraft-p0-engine-cache.gradle` 使用已校验的本地 x86_64 调试引擎缓存。

```powershell
Push-Location android
try {
    .\gradlew.bat :app:assembleDebug --console=plain --info `
      '-Ptarget-platform=android-x64' '-Ptarget=lib/main.dart' `
      '-Pbase-application-name=android.app.Application' `
      '-Ptrack-widget-creation=true' '-Ptree-shake-icons=false' `
      "-Pflutter.androidSdkRoot=$env:ANDROID_HOME" `
      '-Pflutter.installedNdkVersions=28.2.13676358' `
      "-Pflutter.sdkManagerPath=$env:ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager.bat"
} finally {
    Pop-Location
}
```

- 构建结果为 `BUILD SUCCESSFUL`，日志在 `app/build/android-p0-app-assemble.log`。
- APK 位于 `app/build/app/outputs/flutter-apk/app-debug.apk`，104017696 字节，SHA-256 为 `632790216F05E14D7A5447BAF3E34FB400CCCF40E7930C02B23B4CA2A6527D28`。
- `aapt2 dump badging` 核对包名 `com.example.lumacraft`、版本 `0.20.1`（66）、目标 API 36、`x86_64` 和启动入口 `.MainActivity`。`apksigner verify --verbose` 验证 APK v2 签名通过。日志分别为 `app/build/android-p0-apk-badging.log` 和 `app/build/android-p0-apk-signature.log`。
- 安装及首次启动仍待验证。启用 Windows 虚拟机监控程序平台并重启后，用下节命令补齐。

## Android 模拟器首次启动

模拟器配置名为 `LumaCraft_API_31`，配置保存在项目私有的 Android 环境目录。本机 CPU 的固件虚拟化已启用，但 Windows 的 WHPX 查询返回 `HypervisorPresent=False`，模拟器的 `-accel-check` 也报告没有可用的驱动。

软件模式的两次启动测试使用了 `-accel off`，分别使用 SwiftShader 和关闭 GPU。两次均未取得 `sys.boot_completed=1`，ADB 没有可用于安装的设备。系统加速启用后用 `emulator -accel-check` 确认，然后运行以下命令。系统层配置可参考 [Android 模拟器加速官方说明](https://developer.android.com/studio/run/emulator-acceleration)。

```powershell
emulator -avd LumaCraft_API_31 -no-metrics
adb devices -l
adb install -r .\build\app\outputs\flutter-apk\app-debug.apk
adb shell am start -W -n com.example.lumacraft/.MainActivity
```

## 平台边界与数据流

- **选图和工作台。** `main.dart` 的 `Workshop` 同时持有目录树、扫描器、选中照片、预设库、Windows 窗口控制与导出状态。`directory_browser.dart` 用目录路径和系统通知刷新。Android 需要以系统选图、分享接收和 URI 权限建立入口。
- **解码与色彩。** `decodePhotoImage` 对普通照片可走 Flutter 解码。HEIC、广色域 JPG，以及导出的 `openForExport` 进入 `decodeSrgbPhoto`，调用 Windows WIC 辅助程序，并在非 Windows 平台主动返回不支持。Android 必须验证替代解码、照片方向、色彩转换和输出 sRGB 配置。
- **拍摄字段。** `photo_state.dart` 的 `readCapture` 从路径读取源文件字节，再解析 EXIF 和 GPS。`PhotoState.effective` 把手填覆盖与原始字段合并。字段与覆盖规则可共享，URI 读取需换平台入口。
- **样式和渲染。** `StyleDocument`、`StyleScene` 和构图适配规则是主要复用候选。`preset_package.dart` 读取并验证 `.lmp`，其中包含布局和素材检查。未知字段的跨端往返行为仍需验证。
- **成片导出。** `main.dart` 生成批次任务 → `openForExport` 解码转色 → `renderStyledPhoto` 或旧样式渲染 → 编码、EXIF/GPS 策略和 ICC → `publishExport` 写临时文件及发布。命名、尺寸和冲突策略可共享。Android 相册的 MediaStore 或 SAF 需要独立写入实现。现有上限是 16384 像素最长边、134217728 总像素，手机实际可用尺寸待测。
- **持久化和地图。** `PhotoStore.defaultFile` 依赖可执行文件位置或测试环境变量，Android 需要应用私有数据目录。`place_picker.dart` 和 `webview_geocoder.dart` 依赖 Windows WebView，坐标转换和高德页面规则可作为 Android 验证起点。
- **验证样本。** 现有 `app/test/fixtures/heic/` 包含普通 sRGB、Display P3、EXIF/GPS、12MP 网格、方向和异常文件。`heif_import_test.dart`、`export_pipeline_test.dart`、`layout_adaptation_test.dart` 可作为 Windows 对照。P1 再补 24/48/61MP 与 Android 相册、后台和地图场景。
