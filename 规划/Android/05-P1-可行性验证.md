# Android P1 可行性验证

日期：2026-11-10。代码基线 `ac439e138b1c3414dbd3b8188b251368630d1674`，本地分支 `codex/android`。用户已确认 P0 模拟器内应用正常出现，随后手动关机。

## 交付与复测

- 测试包 `app/dist/LumaCraft-Android-P1/LumaCraft-Android-P1-debug.apk`。包名 `com.example.lumacraft.p1`，x86_64，调试签名 v2 已验证，可与 P0 并存。SHA-256 `EEE99ACACBAFAB67A27AB47874F912B4BE821D03A5DF9C5D461B8DF2E9D6AC8D`。
- 以 WHPX、SwiftShader 和禁用 Vulkan 的方式运行 Android 12 API 31 模拟器，虚拟机配置为 2 GiB RAM。应用日志确认 Flutter 使用 Impeller 的 OpenGL ES 后端。
- 双击 `app/tools/启动安卓模拟器.cmd`。本机模拟器已安装测试版，测试样本位于其内部存储的 `Download/LumaCraft-P1`。从应用列表打开新测试版，标题为「LumaCraft · Android P1」，或在 `app` 目录执行以下命令。
- 在测试页点「选择照片」，从系统选图器左侧选择内部存储，然后进入 `Download/LumaCraft-P1`。选择后点「套用画廊签名并保存 JPG」。成片在 `Pictures/LumaCraft P1`。

```powershell

adb -e install -r '.\dist\LumaCraft-Android-P1\LumaCraft-Android-P1-debug.apk'
adb -e shell am start -W -n com.example.lumacraft.p1/com.example.lumacraft.MainActivity

```

## 照片处理结果

| 用例 | 实际结果 |
| --- | --- |
| 普通 JPEG | 系统选图、预览、画廊签名和相册写入通过。1600 × 1200 输入，1696 × 1440 成片。 |
| 带拍摄信息的 HEIC | 1696 × 1440 成片，原相机字段和拍摄时间保留，GPS 按默认策略移除。从已发布的 MediaStore 路径拉回文件，独立核对 JPG 尺寸、EXIF 和 ICC 的完整字节。 |
| 方向标记 6 的 HEIC | Android 解码得到 1200 × 800，与仓库中的 Windows 预期尺寸一致。 |
| 12MP 分块 HEIC | 4032 × 3024 输入，预览 1440 × 1080，导出 4274 × 3629。 |
| Display P3 JPEG | 系统识别为 Display P3，预览和完整解码都输出 sRGB，成片 ICC 验证通过。使用已有 JPEG 像素与公开的 Display P3 ICC 构造测试图。 |
| 10 位 Display P3 HEIC | 模拟器的 ImageDecoder 在创建解码器时失败，系统日志记录 `No valid image or sequence available`。失败发生在色彩转换和 Flutter 渲染之前。待用 ARM64 真机复测同一文件，判断是否需要替代解码。 |

已有 JPEG 和 HEIC 来自 `app/test/fixtures/heic/`，是有代表性的编码测试图。12 至 61 MP JPEG 为生成的合成图。真机拍摄文件、HDR 色调映射和逐像素的跨平台色差还待验证。

平台侧以系统文件选择器取得 URI，并将原始字节流复制到应用缓存。用 [Android ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder) 转成 sRGB 后调用现有 Flutter 样式和导出流程。JPG 使用 [Compact ICC Profiles](https://github.com/saucecontrol/Compact-ICC-Profiles) 的 CC0 sRGB-v2-micro 配置，配置文件 SHA-256 为 `0a8a33aea66a6f154a5642ebe168ef287e73265d9f7b51c42a45e6eedbacda7a`。相册写入使用 [MediaStore](https://developer.android.com/training/data-storage/shared/media)，发布前标记待完成，失败时回收该记录。已读回成片的 `is_pending=0`。

## 大图内存与尺寸

使用应用进程 PSS（KiB）每 250 ms 采样。数值是本次观察到的峰值，可能漏掉瞬时峰值，不代表真机容量保证。12 和 24 MP 为首轮通过记录，48 和 61 MP 为加尺寸校验后的复测。

| 输入 | 预览峰值 KiB | 导出尝试峰值 KiB | 原尺寸结果 |
| --- | ---: | ---: | --- |
| 12 MP，4000 × 3000 | 344051 | 528898 | 4240 × 3600，保存成功 |
| 24 MP，6000 × 4000 | 345860 | 705939 | 6320 × 4800，保存成功 |
| 48 MP，8000 × 6000 | 355285 | 1018412 | Flutter 成片 8192 × 6955，预期 8480 × 7200，拒绝写入 |
| 61 MP，9504 × 6336 | 349474 | 694802 | Android 解码得到 9504 × 6336，Flutter 图像只有 8192 × 6336，在绘制前拒绝 |

初次实验的 48 和 61 MP 都返回了缩小后的 JPG。最终版在 Flutter 接收图像和 JPG 完成后分别检查尺寸，复测前后 MediaStore 成片数量均为 9。当前全帧流程经过临时 PNG、Flutter 图像和 JPEG 编码，内存增长明显。后续应先用 ARM64 真机确认实际渲染上限，再验证避免单张大纹理的分块或 CPU 导出路线，同时保留尺寸校验。

## 构建和证据

在 `app` 目录加载 P0 环境后执行以下命令。构建完成时，Gradle 生成的 P1 APK 位于 `app/build/app/outputs/flutter-apk/app-debug.apk`，复制至交付目录后原路径恢复为 P0 APK。

```powershell
. .\tools\android-p0-env.ps1
Push-Location android
try {
    .\gradlew.bat :app:assembleDebug --console=plain '-PlumacraftP1=true' `
      '-Ptarget-platform=android-x64' '-Ptarget=lib/android_p1.dart' `
      '-Pbase-application-name=android.app.Application' `
      '-Ptrack-widget-creation=true' '-Ptree-shake-icons=false' `
      "-Pflutter.androidSdkRoot=$env:ANDROID_HOME" `
      '-Pflutter.installedNdkVersions=28.2.13676358' `
      "-Pflutter.sdkManagerPath=$env:ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager.bat"
} finally {
    Pop-Location
}
```

- `app/lib/android_p1.dart` 为独立实验入口。Android 侧由 `AndroidP1Bridge.kt` 接系统选图、解码、相册、PSS 和 WebView，`MainActivity.kt` 注册该入口。Debug manifest 的网络策略只放行本机 HTTP。
- `app/build/android-p1-build-final.log` 显示 `BUILD SUCCESSFUL`。P1 Dart 分析有两条字符串插值格式提示，0 警告、0 错误。
- `app/build/android-p1-photo-verification.log` 记录首轮样本，`app/build/android-p1-final-verification.log` 记录修正后 HEIC、P3 JPEG 和大图。 `app/build/android-p1-exif-export.jpg` 是通过 MediaStore 回读的成片。
- `app/build/android-p1-windows-regression.log` 记录 `flutter --no-version-check test --no-pub -j 1 --reporter expanded test/export_pipeline_test.dart test/layout_adaptation_test.dart`，5 项通过。

## ARM64 真机补包

vivo X100 Ultra 的安装界面报告 ABI 不匹配。原 P1 APK 的 ABI 为 x86_64。使用上面的构建命令，将 `-Ptarget-platform=android-x64` 改成 `-Ptarget-platform=android-arm64`，生成独立真机包 `app/dist/LumaCraft-Android-P1/LumaCraft-Android-P1-arm64-v8a-debug.apk`。

`aapt2 dump badging` 确认 `arm64-v8a`，包名为 `com.example.lumacraft.p1`，目标 API 为 36。APK v2 签名、`zipalign -c -P 16 4` 和原生库 ELF LOAD 段的 16 KiB 对齐均已核验。APK SHA-256 为 `0615D895418F649B5E5EB8ADBDC44A053DF7D282DDA66D9DC33F499A7338A150`。vivo 真机安装和功能验证待用户复测。

用户随后在 vivo X100 Ultra（Android 16）确认：61 MP 可原尺寸导出，未遇到模拟器的 8192 像素限制。Display P3 HEIC 能打开、套用预设并导出，用户确认成片颜色正确。
